## RR-001 零售 AI 客服方案安全校验

### Case 信息

- Case ID：RR-001
- Case 名称：零售 AI 客服方案安全校验
- Case 类型：risk_check
- 输入来源：SG-002 方案生成 Agent 输出
- 运行类型：首次运行
- 期望结果：Pass

### 输入

本次风险校验 Agent 的直接输入包括：

- structured_requirement_text：来自「格式化需求与检索问题」Code 节点。
- evidence_retrieval_output：来自「证据检索 Agent」的 structured_output，其中包含 evidence_results 和 retrieval_summary。
- capability_matching_output：来自「能力匹配评估 Agent」的 structured_output，其中包含 capability_assessments 和 assessment_summary。
- proposal_json：来自「方案生成 Agent」的结构化方案结果。
- proposal_text_draft：来自「方案生成 Agent」的自然语言方案初稿。

本次端到端输入口径为售前人员转述客户需求。

第一轮输入：

text 客户反馈他们想做 AI 客服，目标是降低客服压力。请帮我先梳理需求。 

第一轮输出：

text 当前客户需求信息还不完整，暂时无法进入证据检索流程。  请向客户进一步确认，或补充以下客户信息： - 该需求对应的 AI 系统主要服务哪些使用对象？ - 客户希望该 AI 系统具体支持哪些业务功能（如商品咨询、订单查询等）？ - 客户期望的部署方式是什么（如公有云、私有化部署等）？ - 是否需要对接现有系统？如果需要，请确认系统名称。 

第二轮输入：

text 补充信息：客户主要希望给消费者和客服坐席使用，需要支持商品咨询和订单查询，希望私有化部署，并需要对接客户的订单系统。 

### 预期输出

风险校验 Agent 应输出：

1. risk_check_result
2. final_safe_response

其中，risk_check_result 应满足：

- passed = true
- risk_level = low 或 risk_level = medium
- must_block_output = false
- issues 可以为空，也可以记录低 / 中风险问题

final_safe_response 应满足：

- 是完整自然语言方案。
- 面向售前人员。
- 保留初版方案说明、客户需求理解、推荐方案、系统对接与客户配合事项、部署与交付边界、风险与待确认项、下一步建议。
- 明确商品咨询为标准支持能力。
- 明确订单状态查询需完成客户订单系统 API 对接后支持。
- 明确若客户订单系统不开放 API，则无法承诺支持实时订单状态查询。
- 保留客户侧配合事项，包括 API 文档、鉴权方式、字段映射、测试环境、联调窗口等。
- 明确私有化部署仅可评估，具体部署条件、交付周期和费用需交付负责人确认。
- 不得承诺确定报价、确定交期、保证上线、私有化部署一定可交付。

### 实际输出

```text
 # 零售 AI 客服初版方案

## 初版方案说明
本方案是基于当前结构化需求、证据检索结果和能力匹配评估生成的售前初版方案，供售前团队审核。本方案不包含最终客户承诺，所有涉及交付周期、费用及特定技术细节的内容均需进一步确认。

## 客户需求理解
- **业务目标**：降低客服压力。
- **目标用户**：消费者、客服坐席。
- **核心功能**：
  - 商品咨询：基于知识库回答商品规格、使用方式等问题。
  - 订单状态查询：实时查询订单进度。
- **部署诉求**：私有化部署。
- **系统对接**：需对接现有订单系统。

## 推荐方案

### 1. 标准支持能力
- **商品咨询**：AI 客服标准支持基于商品知识库回答商品咨询问题，包括商品规格、使用方式、适用场景、基础参数等。退换货政策问答属于可配置支持能力，需单独配置。

### 2. 需系统/API 对接后支持能力
- **订单状态查询**：AI 客服支持订单状态查询，但必须在完成与客户订单系统的 API 对接后方可支持。若客户订单系统不开放 API，则无法承诺支持实时查询。
- **订单系统对接**：需获取客户订单系统的 API 访问权限，并完成字段映射和鉴权配置。

### 3. 需人工确认能力
- **私有化部署**：AI 客服企业版可评估私有化部署方案，但具体的部署条件、交付周期、费用必须由交付负责人进一步确认，AI 客服团队不能自动承诺。

## 系统对接与客户配合事项
为确保订单状态查询功能的顺利交付，需客户提供以下配合：
1. **API 文档**：提供完整的订单系统 API 文档。
2. **鉴权方式**：明确 API 调用的鉴权方式（如 Token/OAuth）。
3. **字段映射**：提供字段映射要求，以便评估数据同步的可行性。
4. **测试环境**：提供测试环境访问权限，用于联调测试。
5. **联调窗口**：安排合适的联调时间窗口。

## 部署与交付边界
- **私有化部署**：可评估，但需进一步确认交付条件、周期和费用。
- **交付边界**：
  - 退换货政策问答需单独配置。
  - 订单状态查询仅在客户订单系统开放 API 时可交付。
  - 私有化部署需交付负责人介入评估具体环境和资源需求。

## 风险与待确认项
- **风险点**：
  - 依赖第三方系统（客户订单系统）的可用性。
  - 交付周期和费用存在不确定性。
  - 需内部资源协调。
  - 缺少订单系统 API 的具体字段映射要求。
  - 缺少订单系统 API 的鉴权方式说明。
  - 缺少数据同步频率或实时性要求的技术细节。
- **待确认项**：
  - 确认部署条件（服务器配置、网络环境等）。
  - 确认交付周期。
  - 确认最终报价。
  - 联系客户获取订单系统 API 文档。
  - 评估字段映射可行性。
  - 确认鉴权方式（Token/OAuth）。
  - 确认退换货政策的配置细节。

## 下一步建议
1. 针对私有化部署，安排交付负责人介入评估。
2. 针对订单系统对接，向客户索取 API 文档以补充技术缺口。
3. 确认退换货政策的配置细节。
4. 组织售前与技术团队进行内部评审，完善方案细节。
 ```
