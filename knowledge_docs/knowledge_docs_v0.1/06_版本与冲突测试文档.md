# AI 客服版本与冲突测试文档

## 文档目的

本文档用于测试 Agent 是否能识别旧版本、营销描述和当前正式产品能力之间的冲突。

如果本文档与 active 产品能力说明冲突，应优先参考 active 状态的正式产品能力说明和交付边界文档。

## 冲突 1：私有化部署

### 旧版本描述 v1.0 deprecated

文档状态：deprecated

旧版本曾写明：

> AI 客服标准版支持私有化部署。

### 当前版本描述 v2.0 active

文档状态：active

当前正式产品能力说明为：

> AI 客服企业版可评估私有化部署，标准 SaaS 版不直接支持私有化部署。私有化部署需要交付负责人确认客户环境、安全要求、数据隔离和运维边界。

### 处理规则

如果检索同时命中旧版本和当前版本，应标记 possible_conflicts，并以当前 active 文档为更高优先级。

私有化部署应标记为可评估支持，但需要人工确认，不能写成标准版开箱即用。

## 冲突 2：多语言语音客服

### 旧营销材料 unknown

文档状态：unknown

旧营销材料曾写明：

> AI 客服可以覆盖多语言、多渠道、多模态客服场景。

### 当前产品能力说明 active

文档状态：active

当前正式产品能力说明为：

> 当前 AI 客服 MVP 不支持多语言语音客服。

### 处理规则

旧营销材料属于弱证据，不能作为能力承诺依据。

如果客户提出多语言语音客服需求，应标记为 unsupported 或 insufficient_evidence，并进入人工确认。

## 冲突 3：转人工

### 简化销售话术 unknown

文档状态：unknown

销售话术曾写明：

> AI 客服支持一键转人工。

### 技术方案 active

文档状态：active

正式技术方案说明为：

> 转人工能力依赖客户现有客服系统或工单系统是否开放接口，需要确认触发规则、接口能力和人工客服服务时段。

### 处理规则

转人工不能直接写成无条件支持，应标记为 integration_required 或 need_human_confirmation。

## 冲突 4：订单查询

### 销售问答 low quality

文档状态：unknown

销售问答曾写明：

> AI 客服支持订单查询。

### 技术方案 active

文档状态：active

正式技术方案说明为：

> 订单状态查询需要客户订单系统 API 对接，客户需要提供接口文档、鉴权方式、测试账号和字段说明。

### 处理规则

订单查询应判断为 integration_required，而不是 standard_supported。

方案表达必须保留客户系统 API 对接和接口联调边界。
