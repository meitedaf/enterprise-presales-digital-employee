# AI 客服交付边界与人工确认规则

## 1. 文档目的

本文档用于定义 AI 客服项目中的交付边界和人工确认规则，避免售前方案中出现过度承诺。

AI 客服生成的方案只能作为售前可审核的初版方案，不作为正式报价、交期或合同承诺。

## 2. 必须人工确认的事项

以下事项必须由销售、售前、产品、交付或技术负责人确认：

1. 最终报价。
2. 最终交期。
3. 定制开发范围。
4. 私有化部署条件。
5. 客户系统 API 是否开放。
6. 接口联调工作量。
7. 客户数据权限。
8. 合同条款。
9. 涉及赔付、退款、投诉升级的业务规则。
10. 非标准产品能力。

## 3. 报价边界

AI 客服不得自动生成最终报价。

报价通常受以下因素影响：

1. 客户规模。
2. 账号数量。
3. 知识库规模。
4. 系统对接数量。
5. 私有化部署要求。
6. 定制开发范围。
7. 项目实施周期。
8. 商务折扣和审批流程。

方案中只能写：

> 报价需结合部署方式、系统对接范围和实施工作量进一步评估。

不能写：

> 本项目报价为某个确定金额。

## 4. 交期边界

AI 客服不得自动承诺确定交期。

交期通常受以下因素影响：

1. 客户资料准备速度。
2. 知识库清洗和导入工作量。
3. API 开放进度。
4. 接口联调周期。
5. 私有化部署资源准备。
6. 客户验收流程。

方案中只能写：

> 交付周期需在确认知识库范围、接口对接范围和部署方式后评估。

不能写：

> 本项目可在固定天数内完成交付。

## 5. 定制开发边界

历史案例中的定制能力不能直接视为标准产品能力。

如果客户需求涉及以下内容，应标记为定制评估：

1. 非标准渠道接入。
2. 特殊业务审批流。
3. 非标准报表。
4. 特殊权限模型。
5. 客户内部系统深度改造。
6. 多语言语音客服。

方案中只能写：

> 该需求可作为定制需求进一步评估，不应作为标准能力承诺。

## 6. 系统对接边界

涉及订单查询、物流查询、转人工、工单创建、CRM 查询等能力时，必须说明客户侧依赖。

客户侧通常需要提供：

1. API 文档。
2. 鉴权方式。
3. 测试账号。
4. 测试环境。
5. 字段说明。
6. 接口错误码说明。
7. 业务规则说明。

如果客户不能提供 API 或系统接口，则相关能力不能写成确定支持。

## 7. 私有化部署边界

AI 客服企业版可评估私有化部署，但私有化部署必须由交付负责人确认。

需要确认：

1. 客户部署环境。
2. 安全要求。
3. 数据隔离要求。
4. 运维责任边界。
5. 网络访问策略。
6. 日志和审计要求。

方案中不能直接承诺私有化部署价格和交期。

## 8. 历史案例使用边界

历史案例只能作为参考材料，不能直接作为当前客户可交付能力的证明。

如果历史案例中包含定制能力，应明确标记：

> 该能力来自历史定制项目，不代表当前标准产品能力。

## 9. 风险提示表达模板

### 9.1 系统对接类

> 该能力依赖客户业务系统 API，需客户提供接口文档、鉴权方式和测试账号，并在实施阶段完成联调。

### 9.2 私有化部署类

> 私有化部署需结合客户环境、安全要求和运维边界进一步评估，具体交付周期和费用需人工确认。

### 9.3 证据不足类

> 当前知识库未找到该能力的明确支持证据，建议由产品或技术负责人进一步确认。

### 9.4 定制开发类

> 该需求可能涉及非标准定制开发，需单独评估范围、成本和交付周期。
